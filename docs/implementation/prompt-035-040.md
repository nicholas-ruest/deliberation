# Prompts 035–040 implementation evidence

This increment implements ADR-035 through ADR-040: adding the ruvnet dependencies that are a
genuine architectural fit for a gap already in this codebase (AgentDB, agentic-flow) or a
qualified external service reached through this repository's existing dependency-qualification
machinery (federated-mcp, RuLake, SynthLang, RVM). It does not claim any of the six are production
ready — three carry real, documented blockers, and the ADR series is explicit that qualification
is a separate, later step from integration.

## What changed, and its actual qualification state

| ADR | Dependency | Integration | Qualification state | Why |
|---|---|---|---|---|
| 035 | AgentDB | Real npm dependency, `EvidenceSearchPort` + `AgentDbEvidenceSearchAdapter` | `qualifying`, never `eligible` | `npm audit`: 8 HIGH + 22 moderate findings reaching this repo through `agentdb → @huggingface/transformers → onnxruntime-node/sharp` and a duplicated OpenTelemetry tree. None fixable without a breaking downgrade. |
| 036 | agentic-flow | Real npm dependency, `AgenticFlowCostOptimalSelector` behind `ModelGateway`'s existing policy filter | `qualifying`, never `eligible` | Same audit chain as AgentDB (agentic-flow depends on it), plus its own transitive `fastmcp → mcp-proxy → pipenet` (an internet-tunneling tool) — unrelated to the router subpath actually used, but installed regardless. |
| 037 | federated-mcp | Git-visible TypeScript service, `FederatedMcpDiscoveryPort` + HTTP adapter, feeding ordinary `ConnectorRegistration`s | Not modeled as a `ProductionDependency` (discovery-only; nothing becomes callable without separate, existing per-connector approval) | Its real committed HTTP surface is a plain status banner, not the documented API; the adapter targets a clearly-flagged, unverified projection of its in-process `FederationProxy` types. |
| 038 | RuLake | `VectorCachePort` + working `InMemoryVectorCache` baseline + `RuLakeVectorCache` HTTP client | `draft`, never reaches `qualifying` | Zero GitHub releases, no npm or crates.io package — no runnable artifact exists to qualify a version *of*. |
| 039 | SynthLang | Real PyPI dependency, real local sidecar (`scripts/synthlang-sidecar/`), `PromptCompressor` port | `qualifying`, never `eligible` | No supply-chain issue; genuinely requires a held-out compressed-vs-uncompressed output-quality evaluation (ADR-018 non-regression discipline) that does not exist yet. |
| 040 | RVM | `SandboxedExecutionPort` interface + `denyUnqualifiedSandbox` refusal adapter only | `draft`, never reaches `qualifying` | No prebuilt binary anywhere (releases are source tarballs only); bare-metal `no-std` Rust with no Node binding; dispatch mechanism deliberately undecided per ADR-040. |

Three of six (AgentDB, agentic-flow, SynthLang) are real, installed, exercised dependencies with
working adapters that simply are not yet authorized for production traffic — `ModelGateway` and
any future Evidence composition root still refuse to route to them by default, exactly as they
refuse any other unqualified dependency. Two of six (RuLake, RVM) have no runnable artifact to
integrate against at all; what exists is contract scaffolding and a documented refusal. One
(federated-mcp) is real and wired, but deliberately does not carry its own qualification model —
it only ever produces ordinary, individually-approved `ConnectorRegistration`s.

## A real, additional finding from this increment

Wiring AgentDB and agentic-flow surfaced a licensing gap this repository's own `licenses:check`
gate caught: `pipenet@1.4.2` (transitive via `agentic-flow → fastmcp → mcp-proxy`) ships no
`license` field in its `package.json`. Verified by hand against its committed `LICENSE` file (MIT)
and GitHub metadata — a real MIT license, just undeclared — and added as a narrow, justified
exception in `scripts/check-licenses.ts` rather than a silent bypass; see that file for the
verification trail.

## ADR-041: the "held at qualifying" pattern is now an enforced gate, not a convention

The two findings above were handled correctly for AgentDB and agentic-flow, but by hand — nothing
stopped a future change from calling `markEligible(true)` on either while their `npm audit`
findings still stand. ADR-041 records that as a standing policy and `scripts/check-
dependency-qualification.ts` (wired into `npm run quality` as `dependency-qualification:check`)
enforces it mechanically: it cross-references a small, explicit registry of qualification ids
against real `npm audit` output and fails if any registered, currently-flagged dependency is
marked eligible anywhere in `src/`. Proven with real pass/fail fixtures
(`tests/fixtures/dependency-qualification/`) and a fourth test confirming the same fixture passes
once nothing is flagged — the gate tracks current audit state, not a permanent block.

## External release gates

None of the six dependencies in this increment are authorized for production traffic. Clearing
that requires, per dependency:

- **AgentDB / agentic-flow**: the transitive vulnerability chain above resolved or a documented,
  approved risk-acceptance waiver, before `ProductionDependency.markEligible(true)` is ever called.
- **SynthLang**: a held-out evaluation comparing compressed vs. uncompressed model output quality
  on real routes, per ADR-018's non-regression discipline.
- **RuLake / RVM**: a runnable artifact to actually qualify against — neither currently publishes
  one.
- **federated-mcp**: its documented HTTP surface verified against a live instance (this increment's
  contract is explicitly unverified), plus the same per-connector approval every MCP server
  already requires under ADR-008.
